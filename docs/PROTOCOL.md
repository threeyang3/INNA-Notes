# media-video-capture/v1

这是本项目独立使用的本地视频采集交接协议。每条捕获是一份 UTF-8 Markdown 文件，可附带一张 PNG。阅读和处理导出文件不需要 IINA、Obsidian 或 MediaCore 运行。

协议只表达：**用户在某个视频的某个位置，捕获了一张画面及/或写下一段文字。** 不表达作品身份、视频版本分类、观看状态或评分。

## 1. 记录单位与文件布局

| 相对输出根的路径 | 内容 |
| --- | --- |
| `<capture_id>.md` | YAML frontmatter 与正文 |
| `assets/<capture_id>.png` | 可选截图，完整后才能发布引用它的 Markdown |

`capture_id` 是独立生成的身份，不直接用标题、文件名或播放时间替代。同一视频重复捕获、同一位置、同名文件都能够区分。失败重试复用原 ID，不再创建另一条身份。

本实现的 ID 使用字母、数字、下划线和连字符，首字符为字母或数字，长度为 8–101。它是本地捕获身份，不是安全令牌，也不是视频内容指纹。

## 2. 完整示例

下列数值、日期和路径**仅展示格式**，不是运行时默认值，也不是一次真实采集结果：

```yaml
---
capture_protocol: media-video-capture/v1
capture_id: "iina-example-20261118-0001"
capture_player: iina
captured_at: "2026-11-18T20:00:00.123+08:00"
video_title: "示例视频"
video_position_ms: 1938123
video_duration_ms: 7200000
video_was_paused: false
video_source_uri: "file:///Users/example/Movies/example.mkv"
capture_image: "assets/iina-example-20261118-0001.png"
---

![](assets/iina-example-20261118-0001.png)

这里是用户在观看视频时写下的感想。
```

实际文件是以 `---` 开头的 `.md` 文件，YAML 结束后紧接 Markdown 正文。

## 3. 字段定义

所有 frontmatter 字段均为扁平标量，不嵌套对象或列表。

| 字段 | 类型 | 是否必需 | 含义与约束 |
| --- | --- | --- | --- |
| `capture_protocol` | 字符串 | 是 | 固定为 `media-video-capture/v1` |
| `capture_id` | 字符串 | 是 | 稳定的捕获身份；重试不改变 |
| `capture_player` | 字符串 | 是 | 本实现固定为 `iina` |
| `captured_at` | 字符串 | 是 | 触发时的真实日期时间，ISO 8601，含 UTC 偏移或 `Z`；不是保存时间 |
| `video_title` | 字符串 | 是 | 播放器给出的非空标题，可能与源文件名不同 |
| `video_position_ms` | 整数 | 是 | 非负整数毫秒；`1938123` 表示 00:32:18.123 |
| `video_duration_ms` | 整数 | 否 | 已知时为正整数毫秒；未知或无效时省略，不填 `0` 或猜测值 |
| `video_source_uri` | 字符串 | 有条件 | 默认写入规范本地 `file:///` URI；路径隐私开启时省略 |
| `video_source_redacted` | 布尔值 | 有条件 | 隐藏路径时为 `true`，同时省略 `video_source_uri` |
| `capture_image` | 字符串 | 否 | 相对 Markdown 的 `assets/<capture_id>.png`；无截图时省略 |
| `video_was_paused` | 布尔值 | 本实现写入 | 触发时的原始暂停状态，不代表保存后的状态 |

消费端应允许不认识的扩展字段，同时严格验证已知字段类型。不应把字符串形式的数字、负数、非整数、秒数或无法解析的值悄悄当成有效毫秒。未知协议版本应进入待处理流程，不能假定与 v1 完全兼容。

### 时间与画面的精度边界

`video_position_ms` 由真实播放时间换算后取整数。捕获日期、位置、来源和标题在触发时固定，写正文、重试保存不会更新它们。

整数毫秒是**字段单位和存储精度**，不保证截图与解码帧原子采样。读取时间与提交截图是相邻操作；继续播放时可能相差少量帧，不能解释成精确剪辑时间码。需要严格对齐时可先暂停。官方行为见 [mpv：Screenshot Commands](https://mpv.io/manual/master/#screenshot-commands)。

## 4. 隐私与本地路径

关闭「在 Markdown 中保留完整视频路径」后使用：

```yaml
video_source_redacted: true
```

此时不存在 `video_source_uri`，不能填 `file:///redacted`、空字符串或其他假来源。标题、日期和位置仍是真实信息；隐藏路径不是整篇笔记匿名化。

来源按真实 POSIX 路径编码为 `file:///` URI。文件名中**字面的 `%20` 编码为 `%2520`**，不能误当成空格。中文、日文、空格、`#`、`?`、引号、反引号和 `${...}` 都按路径字符处理，不作为查询参数、shell 命令或模板执行。

本轮不采集网络视频，不写入 HTTP 查询令牌、网盘访问凭据等。网络、无效或来源不完整的状态会被拒绝，不生成伪造的成功记录。

私有 JSON 草稿可保留真实路径以支持恢复和一致性核对；隐私开关只控制可同步 Markdown。隐藏路径时，消费端应允许手动关联，不能假定仍可自动回源。

## 5. YAML 与 Markdown

frontmatter 字符串使用正确转义的双引号标量。实现采用兼容 YAML 双引号标量的 JSON 字符串转义，并处理控制字符和行分隔符等；标题中的冒号、井号、引号、反斜线或换行不会成为新字段。

有截图时，正文开头使用标准引用：

```md
![](assets/iina-example-20261118-0001.png)
```

不依赖 Obsidian 专用的 `![[...]]`。图片路径由插件生成，不包含标题，不把任意视频文件名嵌入 Markdown URL。

用户正文按 Markdown 保留，不把链接、代码块、强调标记等全部转义成纯文本，也不把正文重新解释为 frontmatter。消费端和阅读器仍需使用其正常 Markdown 安全策略，不执行其中脚本或外部命令。

允许图片单独成笔记，也允许文字单独成笔记；截图与非空正文至少有一项。

## 6. 发布与恢复

1. 持久保存固定来源、正文、截图状态与捕获 ID 到私有草稿。
2. 建立发布计划，绑定已授权输出根。
3. 检查 PNG 签名、尺寸、分块结构和完整结尾；通过官方 `utils.exec` 调用 macOS `/bin/cp -n`，原生二进制复制到目标卷的 `.iina-staging/*.png.pending`，检查退出码，再通过 `file.handle` 以 64 KiB 分块读取、完整字节比对并验证目标 PNG。图片不通过文本方式复制，运行时不依赖 Node/fs 或外部库。
4. 以不覆盖已有目标的原子创建方式发布 `assets/<capture_id>.png`。
5. 写完整 Markdown 暂存文件，**最后**发布 `<capture_id>.md`，读回核对。
6. 成功后清理本次私有草稿与暂存资源；不因此删除其他文件。

同卷硬链接实现的是单个最终路径的完整发布，**不保证两个文件整体原子提交，也不等同于断电事务保证**。图片成功、Markdown 失败时可能留下未引用图片，后续用原 ID 和目录重试。仅图片存在不能视为整条完成。

重复保存时，已存在且与发布计划一致的结果可识别为同一次成功。相同 ID、内容不同必须报冲突，不静默覆盖。用户手动修改后的 Markdown 不是可随意重写的缓存。

源视频不参与写入，移动或删除源视频不会删除笔记和截图。

## 7. 消费端建议

1. 只扫描用户选定收件箱内的最终 `*.md`，忽略隐藏暂存目录和所有 `.pending`。
2. 确认协议与类型，检查日期、ID 和毫秒单位，不根据扩展名判定完整。
3. 按 `capture_id` 幂等去重。相同标题、文件名或位置都不足以认定身份相同。
4. 存在 `capture_image` 时，核对受限相对路径、无目录穿越，以及图片确实存在且可读。同步可能先传来 Markdown 后传图片，暂缺应稍后重试，不永久标为完整。
5. 保留正文、原始捕获时间与来源。作品和视频版本绑定另行记录，不要求采集器修改导出。
6. 不自动执行正文、URI 或文件名。打开原视频和跳转应是明确操作，并重新确认有效文件身份。

本协议**没有视频内容指纹**。路径与标题只是关联线索，不能仅凭同名文件认定同一视频或剪辑版本。`capture_id` 识别笔记，不识别作品或源文件。

本插件不填写 MediaCore Work UID、内容版本 ID、观看状态、评分或系列关系；这些由消费端和用户决定。首版不定义跨进程启动 IINA 并精确跳转的协议。

## 8. 兼容性

v1 的字段语义和单位应稳定；消费者保留不认识的字段，破坏性变更使用新协议标识。源码内部类名与私有草稿 JSON 不是公开交接协议的一部分。

MediaCore 不是读取或导出的前置依赖。序列化实现见 [src/protocol.js](../src/protocol.js)，真实播放器限制见 [Mac 验收清单](MAC_ACCEPTANCE.md)。
